# P5.1 — Memory lifecycle: archival tier, forgetting, long-horizon rollups

Status: **DRAFT** — design record for the Feature Roadmap board; not yet implemented.
Owner: Devin (implementation) / Hermes (review, regression gate)

## Goal

Give Argos a maturity curve so the store stops growing monotonically. Records should
graduate: active (injected) → archived (searchable, out of the injection pool) →
forgotten (reversible quarantine) — and long-horizon patterns should be compacted
into profile-style summaries. The stated use case is a lifelong assistant; without
this class of work, year-3 stores inject old noise, injection cost climbs, and recall
dilutes. This is the maintenance path the system currently lacks.

## Current state (verified 28 Aug 2026)

- **Write path**: extractor → reviewer → user confirm; versioning
  (`valid_from`/`valid_to`/`superseded_by`), tombstones, write-time value-supersession
  (28/8) — the update side of the lifecycle exists.
- **Maintenance**: `on_session_end` already runs junk-purge + optional distillation
  (`P4.2`, proposals-only, gated, cost-bounded). The hook, KV state table
  (`system_state`), and LLM seam exist and are the reuse points for this spec.
- **TTL**: `context_note` 30d, `event`/`goal` 180d; `facts`/`preferences`/
  `insights`/`relationships` are permanent.
- **Retrieval**: injection pool top-k (k=96); `include_expired`/`include_closed`
  knobs exist as the pattern for an `include_archived` knob.
- **Feedback counters**: `helpful_count` / `dismissed_count` / `retrieval_count` on
  `memory_records`.
- **Missing**: no tier concept, no archival, no forgetting, no rollups.

## Design

Three phases, each independently shippable and independently measured.

### Phase 1 — Archival tier (deterministic, zero LLM)

- New column `tier TEXT NOT NULL DEFAULT 'active'` in the existing schema-init block
  (`CREATE TABLE IF NOT EXISTS` — zero migration; existing rows default `active`).
- Maintenance pass in the session-end hook (beside junk-purge): archive records where
  - `status = 'active'` AND `tier = 'active'`
  - age > `archive_after_days` (default 180, base = `created_at`)
  - `retrieval_count = 0` AND no feedback
  - category NOT in `archive_exempt_categories` (default: `facts`, `preferences`,
    `insights`, `relationships`, `goal`)
- Archived records: excluded from the injection pool and from default search;
  retrievable via `include_archived=True` (same pattern as `include_expired`).
- Revival: any `update_memory` / feedback / explicit re-save on an archived record
  flips it back to `active`.

### Phase 2 — Forgetting (deterministic, zero LLM)

- Auto-quarantine candidates: `context_note`/`event`/`goal` with age >
  `forget_after_days` (default 365), `retrieval_count = 0`, no feedback → move to the
  existing **quarantine** state (reversible, never deleted; user can restore).
- Only recommendations are quarantined — nothing is deleted by policy, ever.

### Phase 3 — Long-horizon rollups (LLM, reuses the P4.2 seam)

- Trigger: same novelty/cooldown/budget machinery as distillation, separate knob
  (`rollup_enabled`, `rollup_interval_days` default 30).
- Input: bounded sample (`rollup_max_records_per_run`, default 100) of the oldest
  active low-retrieval records beyond the rollup horizon.
- Output: **proposals only** (category `insight`/`context_note`, `source='rollup'`,
  `kind='profile'`) — "what has stayed true / what changed" summaries. Nothing writes
  active memory; the standard review pipeline decides. Same fail-soft + `last_run`
  KV semantics as P4.2.

### Phasing rule

Phase 1 → Phase 2 → Phase 3. Each phase must pass the regression gate before the
next starts (see Acceptance).

## Config (config_schema.py, new "Lifecycle" group — MUST be UI-visible)

- `archive_enabled` (bool, default `false` — conservative; enable after soak)
- `archive_after_days` (int, `180`)
- `archive_exempt_categories` (list, default facts/preferences/insights/relationships/goal)
- `forget_enabled` (bool, `false`)
- `forget_after_days` (int, `365`)
- `rollup_enabled` (bool, `false`)
- `rollup_interval_days` (int, `30`)
- `rollup_max_records_per_run` (int, `100`)

## Cost (rand)

- Phases 1–2: **zero** — deterministic SQL in the maintenance pass.
- Phase 3: ≈ P4.2 per-run cost (≈ R0.10–0.60/run; worst realistic ≈ R2–8/month at a
  30-day interval).

## Safety invariants (non-negotiable)

- Archived/forgotten ≠ deleted: both paths are reversible; tombstones untouched.
- Rollups are proposals-only — never auto-activate into retrievable memory.
- Nothing younger than its threshold can be archived/forgotten.
- Phase 3 reuses P4.2's cost caps and fail-soft; an LLM failure never blocks session end.

## Acceptance criteria

- [ ] Injection pool size stops growing monotonically on a seeded test store
- [ ] Archived records excluded from default search; returned with `include_archived`
- [ ] Revival path works (update/feedback revives)
- [ ] Forgetting is reversible (quarantine + restore path, no deletion)
- [ ] Self-corpus gate + LongMemEval bank: no recall regression for active facts (run before/after)
- [ ] Plugin test suite green; new tests: archive policy, revive, rollup proposal path (mocked LLM)
- [ ] Config knobs visible + effective in the Memory & Context UI
- [ ] CHANGELOG entry
