# P4.2 — Distillation pass ("the dream")

Status: **Spec — ready for implementation** (22 Aug 2026)
Owner: Devin (implementation) / Hermes (review)

## Goal

A bounded, LLM-assisted consolidation pass that turns accumulated records + feedback into **distilled proposals**: insights, guardrails/strategies, and contradiction surfaces. It **proposes only** — nothing it emits becomes retrievable memory until the existing review pipeline approves it. This is the learning flywheel Argos lacks. It is **not** a cron job: it ships as a portable Argos feature triggered by the provider's `on_session_end` hook, exactly like `consolidation_enabled` today.

## Current state (verified in fork, hybrid_memory_plugin/)

- **Candidate pipeline exists**: `save_candidate` (store.py:1455 — accepts `payload` dict + `evidence_text` + `dedup=True` with pending-duplicate check), `list_candidates` (1522), `review_candidate` (1549). Flow: pending → auto-review (`_review_candidate`, __init__.py:1935, gated by `auto_review` default true) → user confirm via `memory_candidate_review`. Pending proposals are **invisible to retrieval** until approved.
- **LLM client exists**: plugin already configures `llm_model`/`llm_provider` for aux tasks (extraction, review, query expansion; `_llm` client). The dream reuses it — zero new infrastructure, cost lands on the same billing path.
- **Hook exists**: `on_session_end` (__init__.py:2101) already runs junk-purge + optional `consolidate()`; this is the extension point.
- **Evidence table exists**: `memory_evidence` (store.py:293); `save_candidate` carries `evidence_text` + `payload` for grounding.
- **Feedback signals**: `helpful_count` / `dismissed_count` / `retrieval_count` counters on `memory_records` (no event log — v1 reads counters).
- **Contradiction machinery**: `find_supersede_candidates` (store.py:1696) — conflict resolution already rides the chain-unfold supersede flow, user-confirmed.
- **No KV/state table exists** — the design below avoids adding one.

## Design

### Trigger & gates (the agreed model)

- **Hook**: `on_session_end`, gated by `distillation_enabled` (default **false**).
- **Novelty gate**: eligible-diff = count of active, non-superseded records created/updated since `last_run`. Run only if ≥ `distillation_min_new_records` (default 20). Computed store-side **before any LLM call**.
- **Cooldown**: ≥ `distillation_cooldown_hours` (default 24) since `last_run`.
- **Budget**: sample ≤ `distillation_max_records_per_run` (default 100), ≤ `distillation_max_calls` (default 10) LLM calls per run.
- **Fail-soft**: any exception (LLM error, bad JSON, timeout) → log, abort the leg, never block session end.
- **Crash caveat (accepted)**: if `on_session_end` never fires (force-kill), the pass simply catches up at the next clean end — gates compare against the *last successful run*, and a proposal-only pass has no dangerous backlog behavior.

### The pass — three legs

1. **Cluster scan (deterministic, free)**
   - Load eligible active non-superseded records created since `last_run` (fallback: most recent N if never run).
   - Cluster by embedding cosine ≥ 0.75 into groups of ≤ 8 (looser than P4.1's 0.88 — we want *related-but-distinct* groups, not near-duplicates; P4.1 already owns dedup).
   - Sample clusters down to the run budget (newest first).

2. **LLM distill (1 call per cluster)**
   - Prompt: cluster record contents + counters (helpful/dismissed/retrieval) + strict instruction set:
     - Only derive what the evidence supports; never introduce facts not present.
     - Output strict JSON: `{"insights": [...], "contradictions": [{"a_id", "b_id", "reason"}], "guardrails": [...]}`.
     - Each item < 200 chars, plain declarative sentence.
     - Never suggest merging/deleting records (that is P4.1's job).
     - Low-confidence suggestions flagged (`"confidence": "low"`).
   - `max_tokens` capped (~200) per call; temperature low (e.g. 0.2).

3. **High-signal scan (1 call, optional)**
   - Top feedback records: `helpful_count > 0` (highest first), `dismissed_count > 0` flagged, retrieval-count spikes.
   - Same prompt shape → guardrail/strategy proposals distilled from **successes and failures** (the "outcome ledger" idea, built from this store's own feedback — not copied from elsewhere).

### Output contract — proposals only

- Every emitted item → `save_candidate(category="insight" | "context_note", source="distillation", evidence_text=<grounding record contents>, payload={"sources": [memory_ids], "kind": "insight" | "guardrail" | "contradiction"}, confidence=<LLM self-rating scaled>, dedup=True)`.
- The pending flow then runs exactly as for extraction: auto-reviewer + user confirmation. **The dream never writes active memory.**
- Contradiction outputs: additionally wired to `find_supersede_candidates` so the resolution path (chain-unfold supersede, user-confirmed) is one step away — never auto-superseded.
- **Run state — no new table**: `last_run` = `MAX(created_at)` of candidates where `source='distillation'`. The candidate queue IS the run log. Zero schema migration.

### Config (config_schema.py, new "Distillation" group — MUST be UI-visible, P2A lesson: a field that isn't in the schema isn't wired)

- `distillation_enabled` (bool, default `false`)
- `distillation_min_new_records` (int, `20`)
- `distillation_cooldown_hours` (int, `24`)
- `distillation_max_records_per_run` (int, `100`)
- `distillation_max_calls` (int, `10`)
- v1 reuses `llm_model`/`llm_provider`; an override knob (cheaper dream model) can come later if wanted.

### Cost (quantified, rand)

- ~1–2k tokens in + ~200 out per call on the aux model → ≈ R0.01–0.05/call at current rates.
- Typical run (5–10 clusters + 1 high-signal scan) ≈ R0.10–0.60.
- With 24h cooldown + novelty gate: worst realistic ≈ R10–15/month; usually less — quiet days skip for free.

## Safety invariants (non-negotiable)

- **Proposals only**: nothing the dream emits is retrievable or active until the existing review flow approves it.
- **No editing/deleting of existing records — ever.** P4.1 owns dedup; P4.2 only proposes additions.
- **Grounded**: every proposal cites source memory_ids (`payload.sources`) + `evidence_text`. Ungrounded LLM inventions that review rejects are the *precision metric*, not an accepted loss.
- **Fail-soft**: LLM error / bad JSON / timeout → skip leg, log, continue. Session end never blocked.
- **Deterministic gating**: novelty/cooldown/budget all computed store-side before any LLM call.
- Same `user_scope`/`project_id` discipline as the rest of the store.

## Tests (new file tests/test_distillation.py)

1. Novelty gate: below `min_new_records` → **zero** LLM calls (mock client asserts).
2. Cooldown gate: last run inside `cooldown_hours` → skip.
3. Budget: records sampled to `max_records_per_run`; calls capped at `max_calls`.
4. Output contract: valid JSON → one pending candidate per insight/guardrail, correct category, `source='distillation'`, `evidence_text` populated, `payload.sources` resolves; `dedup=True` blocks exact re-proposals.
5. Fail-soft: LLM exception / malformed JSON → no crash, no candidates, run state still advances so it doesn't retry-spam.
6. Pending proposals invisible to retrieval (status check).
7. Contradiction outputs link via `find_supersede_candidates` but never auto-supersede.
8. Auto-review integration: distilled candidates flow through `_review_candidate` exactly like extraction candidates (no special-casing).
9. Run-state derivation: `last_run` from `MAX(created_at)` of `source='distillation'` candidates; a second run with no new records skips.
10. Existing suite stays green.
