# P4.1 — Semantic merge (dedup upgrade)

Status: **Spec — ready for implementation** (22 Aug 2026)
Owner: Devin (implementation) / Hermes (review)

## Goal

Upgrade `consolidate()`'s duplicate leg from **exact/containment string matching** to **embedding-similarity merging** so semantically near-duplicate memories ("same fact, rephrased weeks apart") get consolidated instead of accumulating forever. Keep everything reversible, deterministic, and free (no LLM calls).

## Current state (verified in fork, argos_plugin/)

- `store.py:2619` — `consolidate(dry_run, max_actions, min_age_days)` selects candidates in 3 buckets: `expired` (priority 0), `duplicate_containment` (priority 1), `stale_unused_temporary` (priority 2). Quarantines only — never hard-deletes. Reports `expired_count`/`expiring_soon_count` (Spec 1 addition).
- `store.py:2608` — `_memory_quality_score(record)`: `confidence*2 + helpful_count*3 + retrieval_count*0.1 − dismissed_count*2 + min(len/1000, 1.0)`. Used to pick keeper vs duplicate.
- Existing dup leg (`store.py:2687-2705`): groups by category, **casefolded exact match or containment** (len ≥ 20), within-category only, keeper = higher quality score.
- Surfaces that call `consolidate()`: `memory_maintenance` tool (dry_run default) + `on_session_end` (`__init__.py:2124`, gated by `consolidation_enabled`). Config fields live in `config_schema.py` "Maintenance" group (`consolidation_enabled`, `consolidation_min_age_days`, `consolidation_max_actions`).
- Every `memory_records` row carries an `embedding` vector (DuckDB DOUBLE[]), and records have `status`, `valid_to`/`superseded_by` (version chains), `expires_at`, `user_scope`, `project_id`, `quarantine_reason`.

## Design

Extend the existing dup leg — same entry point, one new bucket:

1. **Detection (new, within `consolidate()` or a helper)**
   - Load active, non-superseded records (`valid_to IS NULL`, `status='active'`).
   - Compute pairwise cosine similarity **within category only** (cross-category is OFF for v1 — an `insight` derived from a `personal_fact` is NOT a duplicate; add a `duplicate_cross_category_enabled` flag later if ever).
   - Skip pairs where either record: is expired, is quarantined, has `valid_to` set (chain members — chain-unfold already handles those), or content < 20 chars.
   - Only pairs with cosine ≥ `duplicate_min_similarity` count as candidates.
   - Implementation choice: numpy chunked matrix (normalize + dot, upper triangle per category block) is safest; if going full-SQL, remember the DuckDB vector-param pitfall — never bind Python lists per-row in `list_cosine_similarity` (per-row bind ≈1s@1k), use the string + `CAST(? AS DOUBLE[n])` form, and keep the batch ≤ ~100k rows.
   - Cluster resolution: within a connected cluster of near-dupes, resolve greedily — pick the best-scoring record as keeper, quarantine the rest (each against the keeper), never quarantine a record that is itself the keeper of another selection in the same pass.

2. **Rating** — reject the pair (same as existing): keeper = higher `_memory_quality_score` (already exists); tie-break: newer `created_at`, then longer content.

3. **Action** — quarantine the loser with reason `duplicate_semantic`, and **persist the keeper link** in the quarantine record (extend `quarantine_reason` or add a `keeper_id` column — your call, but the audit must show which memory absorbed which). Do NOT rewrite/merge keeper content — content fusion is LLM work and belongs to P4.2. Everything stays reversible via `memory_restore`.

4. **Reporting** — candidate payload includes: cluster size, both IDs + snippets, cosine, keeper id, and the reason label; count `duplicate_semantic` separately in the report dict alongside existing buckets. Dry-run preview shows clusters grouped, not a flat list.

5. **Config (config_schema.py, Maintenance group — MUST be UI-visible, same lesson as P2A: a field that isn't in the schema isn't wired)**
   - `duplicate_min_similarity` (float, default `0.88`) — conservative; tune from real cluster examples, don't guess.
   - `duplicate_semantic_max_pairs` (int, default e.g. `20000`) — batch guard so detection stays bounded on large stores.

6. **Priority** — add `duplicate_semantic` alongside `duplicate_containment` (same priority tier 1).

## Safety invariants (non-negotiable)

- Quarantine only — never hard delete. Restore must work.
- Never merge across `user_scope`/`project_id`.
- Never touch chain members (`valid_to IS NOT NULL`) or expired records.
- No content rewriting — keeper stays byte-identical.
- Deterministic + free: no LLM calls anywhere in P4.1.

## Tests (new file tests/test_semantic_dedup.py)

1. Same fact rephrased (sim ≥ threshold) → detected, loser quarantined with keeper link.
2. Distinct facts (sim < threshold, e.g. "likes coffee" vs "bought car") → untouched.
3. Keeper selection by quality score; tie-break by recency.
4. dry_run=True performs zero writes.
5. Cross-category pairs (insight vs personal_fact) NOT merged at default config.
6. Expired / superseded / quarantined records excluded from detection.
7. Cluster of 3+ near-dupes → exactly one survivor, rest linked to it, no self-quarantine.
8. `duplicate_min_similarity` config honored (raise it → fewer merges).
9. Restore flow: quarantined loser comes back active; keeper untouched.
10. Existing suite stays green (no regressions in consolidate behavior for old buckets).
